# Tabibi Medical Directory Implementation Plan

**Goal:** Build an Arabic-first Ionic + Angular medical directory for Egypt, backed by Supabase, with a public app and a protected admin area.

**Architecture:** One Angular 22 app. Public routes use Ionic 9 components inside a tab shell; `/admin/**` is a lazy route tree using Angular Material. Domain services are the only code that talks to Supabase; the database enforces all authorization through RLS and `security definer` RPCs.

**Tech stack:** Angular 22.1 (zoneless), Ionic 9, Angular Material 22, Tailwind 4, Signal Forms, ngx-translate 18, supabase-js 2, Capacitor 8, Supabase CLI 3 (via `npx`), pgTAP, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-14-tabibi-design.md`

## Global constraints

- No inline templates or styles: every component has `.ts`, `.html`, `.css`.
- Follow `AGENTS.md`: signals, `input()`/`output()`, `inject()`, native control flow, no `standalone: true`, no explicit OnPush, no `ngClass`/`ngStyle`, no `any`.
- Signal Forms for every form. Form inputs are native elements (`input`, `select`, `textarea`) bound with `[formField]` inside a shared `app-form-field` wrapper, so no third-party control adapter is needed.
- Ionic imports come from `@ionic/angular` (v9), never `/standalone`.
- All user-visible text goes through ngx-translate (`public/i18n/ar.json`, `en.json`).
- Only publishable Supabase keys in the frontend. The service role key exists only as an Edge Function secret.
- No hardcoded directory data in the app; no invented doctors or facilities. Seed data is limited to Egypt's 27 governorates and a list of medical specialties.
- Do not upgrade existing dependencies.

## Assumptions

- `environment.ts` is the development Supabase project and `environment.prod.ts` is production.
- Security tests run against a local Supabase stack in Docker (`npx supabase start`). The hosted projects receive migrations with `npx supabase db push` after the owner links the CLI.
- Areas are entered by the admin; only governorates and specialties are seeded.
- Doctor and facility names are stored in one language as entered; lookup tables are bilingual.

## Phase 1 — Foundation

### Task 1: Dependencies and app shell
- Install: `@ionic/angular`, `ionicons`, `@angular/material`, `@angular/cdk`, `@ngx-translate/core`, `@ngx-translate/http-loader`, `@supabase/supabase-js`, `@capacitor/core`, `@capacitor/android`, `@capacitor/ios`; dev: `@capacitor/cli`, `supabase`.
- Modify `angular.json`: `fileReplacements` for production, Material theme, budgets sized for Ionic + Material.
- Modify `src/index.html` (`lang="ar" dir="rtl"`, Cairo font, viewport-fit), `src/styles.css` (Ionic core CSS, Tailwind, theme variables, Material theme).
- Modify `src/app/app.config.ts`: `provideIonicAngular`, `provideHttpClient`, `provideTranslateService`, router with lazy routes.
- Create `capacitor.config.ts`, `.env.example`.
- Check: `ng build` passes; app renders an empty Ionic shell in RTL.

### Task 2: Database schema migration
- Create `supabase/config.toml` (via `npx supabase init`), `supabase/migrations/…_schema.sql`: extensions (`pg_trgm`), tables, constraints, indexes, `normalize_arabic`, `search_text` and `updated_at` triggers, profile-on-signup trigger.
- Check: `npx supabase db reset` applies cleanly.

### Task 3: Security migration
- Create `supabase/migrations/…_security.sql`: `is_admin()`, grants, RLS policies for every table, RPCs `find_duplicate_doctors`, `approve_submission`, `reject_submission`, `admin_dashboard_stats`.
- Create `supabase/migrations/…_storage.sql`: `ad-images` bucket (public, 2 MB, image MIME types) and admin-only write policies.
- Create `supabase/seed.sql`: governorates and specialties.

### Task 4: SQL security tests
- Create `supabase/tests/001_public_access.test.sql`, `002_admin_access.test.sql`, `003_submission_workflow.test.sql`, `004_advertisements.test.sql` (pgTAP).
- Check: `npx supabase test db` passes; each denied case fails for the right reason.

### Task 5: Edge Function
- Create `supabase/functions/submit-doctor/index.ts` and `validation.ts`: CORS, validation, honeypot, hashed-IP rate limit (5/hour), reference checks, insert as `pending`.
- Check: `curl` against local function — valid payload gives 201 and a pending row; invalid gives 400; sixth request in an hour gives 429.

### Task 6: Core Angular services
- Create `core/supabase/supabase.service.ts`, `core/models/*.ts`, `core/auth/auth.service.ts`, `core/auth/admin.guard.ts`, `core/i18n/language.service.ts`, `shared/utils/arabic.ts` (+ spec), `shared/utils/links.ts` (+ spec), `core/ui/toast.service.ts`.
- Interfaces produced: `SupabaseService.client`; `AuthService.{session, isAdmin, signIn(email, password), signOut()}`; `LanguageService.{lang, toggle()}`; `normalizeArabic(text)`; `telHref(phone)`, `mapHref({mapUrl, latitude, longitude})`.
- Check: Vitest specs for `normalizeArabic` and link helpers pass.

## Phase 2 — Public application

### Task 7: Shared components
- `shared/components/`: `loading-state`, `error-state`, `empty-state`, `location-filter` (governorate → area cascade), `contact-actions` (call, map), `form-field`, `ad-slot`, `page-header`.
- `features/locations/locations.service.ts`: `governorates()`, `areasOf(governorateId)`, `specialties()`, cached in signals.
- `features/advertisements/ads.service.ts`: `listForPlacement(placement, governorateId?)`, `imageUrl(path)`.

### Task 8: Public shell and home
- `features/shell/` tabs layout, `features/home/`: search box, location filter, category tiles, `home_top` and `home_middle` ad slots, recently added doctors.

### Task 9: Doctors directory
- `features/doctors/doctors.service.ts`: `search({term, specialtyId, governorateId, areaId, page})`, `getById(id)`.
- `doctors-list` (search, filters, infinite scroll, `doctors_list` ad slot), `doctor-card`, `doctor-detail`.

### Task 10: Facilities directory
- `features/facilities/facilities.service.ts`: `search({type, term, governorateId, areaId, page})`.
- `facilities-list` (type segment, filters, `facilities_list` ad slot), `facility-card`.

### Task 11: Doctor suggestion form
- `features/doctor-submissions/submissions.service.ts`: `submit(payload)` → Edge Function.
- `submission-form` with Signal Forms validation, honeypot, success and error states.

## Phase 3 — Admin

### Task 12: Admin login, shell, dashboard
- `features/admin/login`, `shell` (side nav, responsive), `dashboard` (six counters from `admin_dashboard_stats`).
- `features/admin/shared/`: `confirm-dialog`, `crud-table` helpers.

### Task 13: Governorates, areas, specialties management
- List with search and active filter, add/edit dialog, activate/deactivate.

### Task 14: Doctors and facilities management
- Tables with search, filters and pagination; add/edit dialogs with governorate → area cascade; activate/deactivate; delete with confirmation.

### Task 15: Submissions review
- Pending/approved/rejected filter, detail dialog with duplicate list, approve (specialty resolution, allow-duplicate confirmation), reject with note.

### Task 16: Advertisements management
- Table, add/edit dialog, image pick → resize to ≤1200 px WebP → upload, replace and delete with storage cleanup, order and active toggle.
- `shared/utils/image.ts`: `resizeToWebp(file, maxWidth)`.

## Phase 4 — Validation

### Task 17: Verification and docs
- Run `npx supabase test db`, `ng test`, `ng build`.
- Browser pass at mobile width: browse, filter, submit; admin: approve, CRUD, image upload.
- `npx cap add android` / `ios` configuration.
- Rewrite `README.md`: install, configuration, migrations, function deploy, admin creation, native builds.
